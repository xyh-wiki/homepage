# 浏览器本地工具真的不上传文件吗？一份实用核对清单

“本地处理”通常表示主要计算发生在浏览器中，但它不是一个可以脱离实现细节的标签。页面可能同时加载统计、广告、登录或远程 API；这些请求未必上传文件，却会改变整体隐私边界。

## 先看工具实际请求了什么

使用非敏感样本打开浏览器开发者工具，在 Network 面板中观察请求。选择文件前记录一次页面请求，选择文件并执行操作后再比较新增请求。重点看请求方法、目标域名、请求体大小和返回内容。

如果执行本地任务时出现与文件大小接近的上传请求，或者请求体中包含文件内容，就不能把它当作纯本地处理。无法理解的第三方域名也应先查清用途。

## 检查脚本和权限边界

网页工具依赖 JavaScript 并不等于不安全，但脚本来源和权限应当与功能匹配。处理文件的页面可能使用 Web Worker 或 WebAssembly；这类资源仍然应该来自可信来源，并且不应要求与任务无关的账户权限。

浏览器扩展、桌面包装器和带登录的版本可能有不同的数据流。不要把一个版本的隐私说明自动套用到另一个版本。

## 区分文件数据和访问数据

即使文件没有上传，托管服务仍可能收到 IP 地址、访问路径、时间、浏览器类型和安全日志。广告与统计服务也可能根据自己的配置处理设备和访问信息。隐私判断应同时覆盖“文件内容是否离开设备”和“访问行为会留下什么记录”。

查看隐私政策时，注意它是否说明：

- 文件是否发送到服务器；
- 文件和结果保存多久；
- 第三方脚本或接口由谁提供；
- 错误日志是否包含文件名或输入内容；
- 用户如何删除数据或撤回同意。

## 处理敏感文件时的保守做法

对密码、访问令牌、身份证明、客户资料、医疗信息和生产文档，优先使用组织批准的本地工具。必须使用网页工具时，先脱敏并用测试样本验证请求，再确认输出没有把敏感内容带入文件名、日志或分享链接。

不要仅因为页面写着“免费”或“无需注册”就认为没有数据处理。免费服务也可能依赖广告、分析或第三方接口。

## 如何记录一次检查结果

可以用一张简单记录表保存页面地址、检查日期、测试文件类型、观察到的请求域名、是否发现上传、结果保存位置和隐私政策版本。以后工具升级时重新检查，避免把过去的观察当成永久保证。
